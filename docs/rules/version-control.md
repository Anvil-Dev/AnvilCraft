# 提交与版本控制

本规范约束提交粒度、提交信息、暂存范围与推送行为。准备提交、修改历史或推送前先阅读本文全文。

## 提交粒度

每个阶段完成后立即执行 `git commit`（无论是任务自然拆分的阶段，还是用户指定的阶段），禁止把多个阶段攒到最后一次性提交。每个提交必须能够独立编译通过，且不依赖同一批次里尚未提交的改动。多个阶段按依赖顺序提交，被依赖的底层改动先提交。

## 提交信息

提交信息遵循 Conventional Commits 格式：`type(scope): 简短中文摘要`；需要正文时用 `- ` 逐条列出交付的具体功能或产物，禁止描述开发过程。

## 暂存与提交前检查

只暂存本阶段相关的文件，禁止将无关改动、构建产物、本地测试数据或他人修改混入提交。提交前必须执行 `git diff --check`、`git diff --cached --check` 以及 `git diff --cached --stat`，并执行 `git status --short` 确认未遗漏新增的未跟踪生成物。

提交前必须完成该阶段对应的编译、单元测试或运行验证，并在向用户汇报时明确列出已执行的验证命令，以及任何未能完成的检查项。

## 推送规则

用户未明确要求推送时，所有提交仅保存在本地，禁止执行 `git push`。当用户明确要求推送时，先执行 `git fetch` 检查远程更新；若远程存在新提交，使用 `git pull --rebase` 合入并解决冲突后，再推送至远程仓库。
