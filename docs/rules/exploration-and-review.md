# 代码探索、工具与子代理审查

本规范约束检索工具选择、探索范围与子代理审查流程。开始大范围检索、查阅依赖源码或分派审查子代理前先阅读本文全文。

## 工具调用优先级与限制

优先使用专用工具与 IDE MCP。处理 Java 项目时，优先使用 IntelliJ IDEA MCP 工具配合 `workspace-agent-bridge` 技能检索项目与依赖库源码；仅当 IDEA MCP 检索依赖源码失败时，允许在 `~/.gradle/caches/` 下检索本地已缓存的源码包（`sources.jar`），禁止通过命令行联网抓取或反编译二进制包。

命令行工具（bash、powershell 等）优先级最低，仅在专用工具无法完成或需要使用基础 Unix 文本工具快速查看时使用。除非用户明确声明处于离开状态（AFK），否则禁止调用命令行执行全屏显示、弹出 GUI 窗口或截图验证等打断用户操作的行为。禁止使用跨会话保留的自动文件式记忆。

## Explore 模式规范

- 必须使用并行工具调用提高检索效率。
- 优先使用文件通配符定位目标模块，再对该模块目录执行合并正则搜索；禁止执行碎片化的单次小范围搜索（如大量单次 `grep`、`sed`），禁止执行无过滤条件的全盘扫描（如扫描构建产物或依赖缓存目录）。
- **禁止调用任何带有 `rm -rf` 字样的命令**。
- 跨项目探索时，优先在项目同级父目录搜索相关源码，禁止在探索源码前解包二进制文件硬读逻辑。

## 子代理协同审查

- 完成中大型编码或重构任务（涉及公共接口、跨模块、多文件、数据迁移、并发、安全、性能关键路径）后，若环境支持，应当派发审查子代理（通常使用轻量级模型）核查变动代码；若待分配任务仅有一两个简单步骤，或当前环境不支持子代理，由主代理直接完成并按相同标准自审，避免上下文丢失与重复检索。
- 严格限制子代理的检索边界：防止子代理查看不属于其任务分片的文件，防止子代理执行未被要求的查询，禁止执行 $N^2$ 复杂度的交叉检查。
- 审查流程：子代理先阅读项目规范与对应 `SKILL`；以只读方式检查代码，指出违反本规范的条目（含违规注释与文风套话，需给出文件、位置、原因和修改建议），并指出潜在的逻辑漏洞、边界遗漏或测试缺口。
- 主代理复核审查意见，决定修复或说明不采纳的理由；修复后必要时再次审查。代码审查不能替代实际的编译、构建和运行验证。
- 审查结论分为必须修复（违反规范、导致错误、引入安全风险、破坏接口要求）、建议修复（潜在缺陷、可维护性问题）和可选改进（不阻塞交付）。
